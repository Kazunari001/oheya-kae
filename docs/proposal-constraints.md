# 配置案の条件

`layout propose --constraints constraints.json`で構造化条件を指定できます。
例えば、次のJSONは棚を固定し、デスクを先に探索します。

```json
{
  "fixedIds": ["shelf"],
  "priorityIds": ["desk"],
  "rotations": [0, 45, 90, 180, 270],
  "clearance": 500
}
```

IDは実在するルートを指定します。固定した親の子孫は相対配置ごと固定されます。
priorityIdsは移動可能な家具ルートのみで、配列の先頭を先に配置します。
fixedIdsとの重複、不明ID・条件名は拒否します。rotationsは1〜12個の有限な角度で、
360度を法として正規化します。省略時は従来どおり0・90度です。
clearanceは0〜5000mmで、JSONの値がCLIの--clearanceに優先します。
これは家具ルートの外接範囲どうしの希望間隔で、通路の連結性は保証しません。
子や独立小物に対しては幾何的な衝突を検証し、同じ希望間隔は保証しません。

探索対象は家具の床置きルートです。独立小物・壁掛けは固定し、子は相対位置を
保って親へ追従します。priorityIdsで子を直接移動する指定は拒否します。
自然言語は従来の仕事関連キーワードだけを扱い、任意の意味は理解しません。

配置できない物体はNO_FEASIBLE_GRID_POSITIONをnotesへ記録して元位置を残し、
最終配置を再検証します。これは指定グリッドで候補がないことを意味し、数学的な
配置不能の証明ではありません。同じ結果の案にはDUPLICATEと先行案IDを表示します。
従来の件数契約を維持するため重複案も返します。

返却された各案のsearchにelapsedMs、evaluated、movableCount、gridCellsを含めます。
searchは実行診断で保存時には残しません。条件と注意はnotes/intentに残ります。
最大30,000グリッド点・合計2,000,000候補評価に制限し、超過時は保存前に拒否します。
物体数・回転数が多い場合は--stepを増やすか--countを減らしてください。

`node scripts/proposal-benchmark.js`で5・15・30物体、8000mm角、400mmグリッド、
3案の合成負荷を再測定できます。結果は時間・評価候補数・幾何判定のJSONです。
